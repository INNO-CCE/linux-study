## 1. 核心策略

1. **项目驱动，不要等「学完」再做。**
2. **输出倒逼输入**：代码 + GitHub + 技术博客 + 项目文档。
3. **尽早实习**：日常实习 → 大厂暑期实习 → 秋招。**边投边补，不要等准备好。**
4. **围绕岗位要求学习**：C/C++、Linux 系统编程、驱动、ARM、调试、协议。
5. **【新增】C++ 是主线，不是加分项。** 2026 年的嵌入式岗位，C++ 和 C 是并列的硬通货。详见第 5 节「2027.2—3」。
6. **【新增】开源贡献是最高杠杆。** 一个被 merged 的 patch > 三个教程项目，因为它证明你能读真实代码库、遵守社区规范、经受 review。
7. **【新增】让论文和求职共用同一个项目。** 导师无指导时，你需要「提案」而不是「请示」。详见 `docs/ZYNQ-路线调整.md` 第四节。

## 2. 方向定位

### 主线（求职用）

**嵌入式 Linux 驱动 / BSP / 系统软件。**

### 差异化标签（针对你的背景）

**ZYNQ 软硬协同 + 边缘 AI。** 你的实验室是 ZYNQ，这天然覆盖了 ARM + 嵌入式 Linux + FPGA 加速三件事，同时命中三类岗位：

- 嵌入式 Linux / 驱动 / BSP —— 华为、中兴、海康、大华、比亚迪
- FPGA / 软硬协同 / 异构计算 —— AMD(Xilinx)、中电科各所、航天科工、雷达通信研究所
- 边缘 AI / 端侧推理 —— 地平线、瑞芯微、工业视觉

### 三条并行能力线

| 线 | 内容 | 起止 |
| :-- | :-- | :-- |
| **语言线** | C 进阶 → C++（类/RAII/多态/模板/移动语义） | 全程 |
| **系统线** | Linux 系统编程 → 驱动 → 内核源码 → 系统移植 | 全程 |
| **工程线** | Git/Makefile/GDB → 调试体系 → 开源贡献 | 全程 |

**三条线要同时推进，不要串行。** 很多人失败在「先把 C 学完再学 Linux，学完 Linux 再学驱动」，结果三年只学完 C。

## 4. 研一上：2026.10—2027.1

> **本阶段唯一目标：把「C + Linux 系统编程 + 工程工具链」变成本能，并在 QEMU 上跑通自己的第一个内核模块。**
> **本阶段不要做的事**：不要买 ZYNQ 板、不要装 PetaLinux、不要碰 Yocto。

### 2026.10：工具链 + C 进阶

- **C 语言进阶**（重点是「为什么」，不是语法）
  - 指针、函数指针、函数指针数组（状态机 / ops 表）
  - 内存布局：栈、堆、BSS、数据段；`static` 的三种语义
  - 结构体对齐与 `offsetof`；`volatile` 到底解决什么
  - 手写数据结构：链表、栈、队列、哈希表
- **Linux 环境与工程工具**（已完成大半 ✅）
  - Ubuntu ✅、VSCode ✅、Git 身份与 GitHub 仓库 ✅
  - **Makefile 三步演化**：显式规则 → 变量 → 模式规则 + 自动依赖（`-MMD -MP`）
  - **GDB**：断点 / 条件断点 / `watch` / `bt` / `frame` / `x/` / core dump 分析
- **算法**：本周开始，每周 2 题（只占周末）
- **产出**
  - GitHub 仓库 `linux-study`（✅ 已建）
  - 一个多文件 C 项目，`-Wall -Wextra -Werror` 零警告，能用 Makefile 编译、GDB 调试
  - 1 篇 problem-driven 博客

### 2026.11：Linux 系统编程

- **文件 I/O**：`open/read/write/lseek/close`、`FILE*` 与 `fd` 的关系、缓冲、`errno` 与 `perror`、`umask`
- **进程**：`fork`/`exec`/`wait`、写时复制（COW）、僵尸进程与孤儿进程
- **线程**：`pthread`、互斥锁、条件变量、生产者-消费者
- **进程间通信**：`pipe`/`FIFO`、共享内存 + 信号量、消息队列、`mmap`
- **I/O 多路复用**：`select`/`poll`/`epoll`，LT 与 ET 模式的坑
- **网络**：TCP/UDP socket、字节序、粘包与拆包
- **配套工具**：`strace` / `ltrace` 黑盒观察系统调用（排查「程序卡住」的第一工具）
- **产出**
  - 主线项目进化到 v0.2（系统调用重写）、v0.3（多进程/多线程）、v0.4（C/S 架构）
  - 多线程 TCP 文件服务器 / 聊天室
  - 技术博客 2—3 篇（problem-driven）

### 2026.12：QEMU 上的驱动入门 + 硬件决策

- **先不买板子，在 QEMU 上学原理**（零成本、可无限次搞崩、能单步调内核）
  - 用 **Buildroot** 生成 `qemu_aarch64_virt` 的内核 + 根文件系统，手工编译一次内核
  - **动手重点**：搞清「内核 + 设备树 + 根文件系统」三者各自是什么、怎么拼起来
  - 内核模块：编写、编译、`insmod`/`rmmod`/`lsmod`/`modinfo`
  - `file_operations`、字符设备注册（`alloc_chrdev_region` + `cdev` + `class_create`/`device_create`）
  - 设备树基础语法：`compatible`、`reg`、`interrupts`、`status`
- **硬件决策**（本月必须做完）
  1. **先借**：问师兄/导师借一块 Zynq-7000 板 —— 大概率有且闲置
  2. 借不到 → 买 **i.MX6ULL**（正点原子或野火，300—500 元），比 ZYNQ 更适合第一次上真板
  3. 顺便买**逻辑分析仪**（100—300 元），调 I2C/SPI 时比自己猜时序快 10 倍
- **复习 STM32**：中断、DMA、I2C、SPI（面试会问裸机经历）
- **ARM 体系**：寄存器组、异常等级、中断向量、MMU 基础、Cache 一致性概念
- **产出**
  - QEMU 上跑通完整 Linux（自编译内核 + Buildroot 根文件系统）
  - 第一个字符设备驱动：注册、`read`/`write`、用户态测试程序

### 2027.1：第一个驱动项目

- GPIO LED、按键中断、I2C 温湿度传感器（**有真板就在真板上做，没有就继续 QEMU + 虚拟设备**）
- 中断下半部：tasklet / 工作队列 / threaded IRQ 的选择依据
- 并发控制：自旋锁、互斥锁、信号量、原子操作
- **产出**
  - 字符设备驱动 + 设备树 + 用户态测试程序，作为独立 Git 仓库
  - **项目 README + 调试记录**（调试记录比代码值钱）
  - 寒假复盘：完成一次 `docs/PLAN-REVIEW.md` 第五节的能力自评

## 5. 研一下：2027.2—2027.6

### 2027.2—3：驱动进阶 + C++ 进主线

- **【新增重点】C++ 开始每日并行**（学法是「唤醒 + 补齐」，不要读《C++ Primer》全本）
  - 顺序：类与构造析构 → 拷贝控制（三/五法则）→ RAII 与智能指针 → 继承与虚函数 → 模板基础 → 移动语义
  - **最佳练法：把研一上写的 C 项目用 C++ 重写一遍**，同一个问题两种语言解，面试直接可讲
  - 参考：《Effective C++》/《Effective Modern C++》做查漏 + cppreference 查语法，**以写代读**
  - 刷题时**刻意用 C++ 的方式写**（用 `unique_ptr` 管链表节点），刷题本身就在练 C++
- **驱动进阶**
  - platform 驱动模型、`probe`/`remove`、设备树匹配
  - 输入子系统、I2C/SPI 子系统（`i2c_driver`/`i2c_client`/`i2c_adapter` 的关系）
  - 中断上半部/下半部划分、`request_threaded_irq`
  - 并发保护实战：说清楚你保护了哪个数据结构、为什么选那把锁
- **产出**：一个 platform 驱动项目 + 一个 I2C/SPI 传感器驱动

### 2027.4：系统移植（上真板）

- U-Boot 移植与裁剪（`board_init`、DDR 初始化、启动流程）
- Linux 内核配置、编译、裁剪（`menuconfig`、defconfig、启动时间优化）
- 根文件系统：BusyBox → Buildroot
- **产出**：从零构建可启动的嵌入式 Linux 系统；记录移植过程中每一个卡点
- **注意**：这一阶段再用 PetaLinux 这类厂商工具是合理的，因为底层原理你已经懂了

### 2027.5：综合项目 + 简历 + 投日常实习

- **综合项目要往「深挖型」做**（判断标准见第 11 节）：有指标、有对比、有取舍
- 简历：项目按 **STAR** 写，但必须有**数字**（延迟、内存、吞吐、启动时间）
- 投递：中小厂、初创公司、研究所的嵌入式软件/驱动实习

### 2027.6：面试、复盘与模拟

- 复习：C / C++ / Linux / 驱动 / 网络 / OS
- 补 FreeRTOS：任务调度、信号量、队列（面试常问裸机与 RTOS 对比）
- **至少 3 次模拟面试**（同学互面，或录下来自己看 —— 你会发现表达问题比知识问题多）
- **产出**：1—2 个可展示项目；第一份实习面试记录与复盘

## 7. 研二上：2027.9—2028.1

### 确定细分方向（三选一，但都保留 C++ 主线）

| 方向 | 内容 | 适合谁 |
| :-- | :-- | :-- |
| **驱动 / BSP** | 内核、设备树、系统移植、稳定性、开源贡献 | 喜欢底层、有耐心读源码 |

| **嵌入式 AI / 异构计算** | ZYNQ DPU、瑞芯微 NPU、模型部署与量化 | **电子信息背景最自然的选择** |

> **推荐**：以「驱动/BSP」为主轴（这是你的核心竞争力），以「ZYNQ + 边缘 AI」为差异化标签，两条腿走路。

### 【新增】开源贡献起步

- 目标不是「给内核提交功能」，现实路径是：
  - `Documentation/` 修正错误、`drivers/staging/` 修编译警告和 checkpatch 问题、设备树补节点
  - 或门槛更友好的项目：**U-Boot、Buildroot、Zephyr、RT-Thread、LVGL、FFmpeg**
- **节奏：每月 1 个 patch。** 第一个 patch 花 2 个月很正常，第二个就快了
- 前置技能：`git rebase` / `format-patch` / `send-email`、读懂 `MAINTAINERS`、会用 `checkpatch.pl`

### 【新增】内核源码阅读

**每月精读 1 个子系统的最小闭环**，从用户态入口一路追到内核。工具：[elixir.bootlin.com](https://elixir.bootlin.com)（必备）+ 本地 `cscope`/`ctags` 索引。

| 月份 | 专题 |
| :-- | :-- |
| 9 月 | `open()` → `sys_open` → `do_sys_open` → `vfs_open` |
| 10 月 | `read`/`write` 的 VFS 路径 + 字符设备 `file_operations` |
| 11 月 | `module_init` 到模块注册的完整链路 |
| 12 月 | `platform_driver_register` + 设备树 `of_*` 解析 |
| 1 月 | I2C 子系统 / 中断子系统（挑一个） |

### 准备大厂暑期实习

- **算法**：Hot 100 第一遍应在 2027.6 前完成，本阶段转为复习 + 刷目标公司真题
- **八股**：C/C++、操作系统、计算机网络、Linux 驱动、ARM —— 用 `docs/PLAN-REVIEW.md` 第五节的清单自测
- **简历：2027.12 前定稿。** 部分公司暑期实习提前批在 **2028 年 1 月**就开放，不要等到 3 月才写简历
- 关注提前批与「日常实习转暑期实习」的机会

## 10. 贯穿三年的固定动作

这几件事与阶段无关，从 2026.10 起一直做到 2029.6：

| 频率 | 动作 | 备注 |
| :-- | :-- | :-- |
| **每周** | **2 道算法题** | 只占周末，按专题刷不按题号刷；**必须写题解** |
| **每周** | **≥3 次 Git 提交** | 唯一客观的产出证据，比「学了多少」重要 |
| **每周** | **≥1h 英文精读** | LWN.net 文章 或 datasheet 章节；不要只看中文二手资料 |

## 11. 项目作品集（v2 修订）

### 原则：宁要一个能讲 20 分钟的项目，不要六个只能讲 2 分钟的

**「深挖型」的判断标准 —— 不是功能多，而是有指标、有对比、有取舍：**

| ❌ 教程型 | ✅ 深挖型 |
| :-- | :-- |
| 「我用 MQTT 把温湿度传到服务器了」 | 「网关在 200 并发下内存从 8MB 涨到 40MB，用 valgrind + perf 定位到是每条消息都 malloc 了一个 4KB 缓冲，改成环形缓冲池后稳定在 12MB，P99 延迟从 80ms 降到 9ms」 |
| 「我移植了 U-Boot」 | 「卡在 DDR 初始化，通过对比 vendor 的 SPD 参数和 `readl` 打印寄存器值定位到问题，记录在文档里」 |
| 「我写了字符设备驱动」 | 「我的驱动在中断里调用 `copy_to_user` 导致偶发 oops，改用工作队列 + 环形缓冲后消除；附 ftrace 截图证明中断延迟改善」 |

### 推荐的作品组合（3+1）

1. **主线进化项目**（`minitool` 类）—— **同一个项目连续 4 周进化**，展示从 libc → 系统调用 → 并发 → 网络的完整能力链。Git 历史本身就是成长曲线。
   - W1 多文件 C + Makefile + GDB → W2 系统调用重写 + errno → W3 多进程/多线程 → W4 Socket C/S
2. **深挖型性能/稳定性项目** —— 有数据、有对比、有取舍的那一个（最重要）
3. **ZYNQ 差异化项目** —— PS-PL 协同：PL 侧一个 AXI 外设 → PS 侧 Linux 驱动控制它 → 进阶 AXI DMA + 边缘推理。**这个项目同时供论文和求职用**
4. **开源贡献记录** —— 不需要是「项目」，一个 merged 的 patch 就是一个作品

### 备选练习项目（做过即可，不必都做）

I2C/SPI 传感器采集 + MQTT + SQLite ｜ 智能家居网关 ｜ V4L2 + FFmpeg + RTSP 视频监控 ｜ RK3568 NPU 部署 YOLO

## 13. 节奏与止损

### 底线 + 弹性（不要设天花板，要设底线）

| | 内容 |
| :-- | :-- |
| **底线（雷打不动）** | 每天 **1 小时**，状态再差也要做。做不到就第二天补，**不允许连续两天为零** |
| **弹性（上不封顶）** | 状态好、周末、没课的时候做 4—8 小时，不设上限 |
| **止损机制** | 连续两周没达到底线 → **不要自责，立刻把当前任务砍掉一半**，从最小可完成量重启 |

> **为什么改掉 v1 的「工作日 2—3h + 周末 5—6h」？** 那个量对研一偏高，而且**太脆** —— 一旦某周没达标，人容易产生「我已经落后了」的挫败感然后彻底放弃。这是自学规划最常见的死法。

### 博客：必须 problem-driven

> ❌ 《Linux 文件 I/O 学习笔记》
> ✅ 《我的 `read()` 在 NFS 上返回 0 但文件非空 —— 一次 errno 排查记录》

文章结构固定为：**现象 → 我的错误猜测 → 排查过程 → 真正原因 → 如何避免**。后者的价值是前者的 10 倍，因为它证明你解决过真实问题，面试时可以直接讲。

## 16. 避坑清单（v2 修订）

1. **不要一直停留在 STM32 裸机**，除非确定走 MCU 方向。
2. **不要只看视频不动手**，驱动必须自己编译、加载、调试。
3. **不要忽略 Git、Makefile、GDB** 等工程工具 —— 它们不是「附带的」。
4. **不要等「完全准备好」才投实习**，边投边补。
5. **不要只做教程项目**，要做有指标、有对比、有取舍的深挖型项目。
6. **不要只写知识总结式博客**，要写问题排查记录。
7. **不要等买开发板才开始** —— QEMU 今天就能开始。
8. **不要把 C++ 留到研二** —— 它会成为面试的硬伤。
9. **不要看中文二手资料学内核** —— 普遍滞后 5—10 年。
10. **不要装 PetaLinux / Yocto 入门** —— 抽象层太厚，学不到原理。
11. **不要设高目标然后失败放弃** —— 设底线，允许弹性。
12. **不要等到研二下才写简历** —— 提前批 2028 年 1 月就开。
13. **不要做和毕业论文无关的项目** —— 让论文和求职共用一件事。
14. **不要被动等导师安排** —— 导师无指导时，你要「提案」而不是「请示」。
15. **不要用 AI 生成你看不懂的代码** —— 面试官会让你讲你自己的代码。
