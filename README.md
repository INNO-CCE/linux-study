# 嵌入式 Linux 三年学习与求职规划

- 适用对象：信息工程本科、电子信息工程专硕，有 C 语言和单片机基础，研一，目标嵌入式 Linux 开发。
- 实验室背景：方向以 ZYNQ 为主，导师无具体指导，基本靠自学。
- 规划起点：2026 年 10 月 10 日。
- 时间假设：三年制专硕，2029 年 6 月毕业，2028 年秋招。

---

## 1. 核心策略

1. 项目驱动，不要等「学完」再做。
2. 输出倒逼输入：代码、GitHub、技术博客、项目文档。
3. 尽早实习：日常实习 → 大厂暑期实习 → 秋招。边投边补，不要等准备好。
4. 围绕岗位要求学习：C/C++、Linux 系统编程、驱动、ARM、调试、协议。
5. C++ 是主线，不是加分项。2026 年的嵌入式岗位，C++ 和 C 是并列的硬通货。详见第 5 节。
6. 开源贡献是最高杠杆。一个被合并的补丁胜过三个教程项目，因为它证明你能读真实代码库、遵守社区规范、经受 review。
7. 让论文和求职共用同一个项目。导师无指导时，你需要提案而不是请示。

## 2. 方向定位

### 主线（求职用）

嵌入式 Linux 驱动 / BSP / 系统软件。

### 差异化标签

ZYNQ 软硬协同加边缘 AI。实验室方向是 ZYNQ，它天然覆盖了 ARM、嵌入式 Linux、FPGA 加速三件事，同时对应三类岗位：

- 嵌入式 Linux / 驱动 / BSP：华为、中兴、海康、大华、比亚迪
- FPGA / 软硬协同 / 异构计算：AMD（Xilinx）、中电科各所、航天科工、雷达通信研究所
- 边缘 AI / 端侧推理：地平线、瑞芯微、工业视觉

### 三条并行能力线

| 线 | 内容 | 起止 |
| :-- | :-- | :-- |
| 语言线 | C 进阶 → C++（类、RAII、多态、模板、移动语义） | 全程 |
| 系统线 | Linux 系统编程 → 驱动 → 内核源码 → 系统移植 | 全程 |
| 工程线 | Git/Makefile/GDB → 调试体系 → 开源贡献 | 全程 |

三条线要同时推进，不要串行。很多人失败在「先把 C 学完再学 Linux，学完 Linux 再学驱动」，结果三年只学完 C。

## 4. 研一上：2026.10—2027.1

- 本阶段唯一目标：把 C、Linux 系统编程、工程工具链变成本能，并在 QEMU 上跑通自己的第一个内核模块。
- 本阶段不要做的事：不要买 ZYNQ 板、不要装 PetaLinux、不要碰 Yocto。

### 2026.10：工具链与 C 进阶

- C 语言进阶，重点是「为什么」，不是语法
  - 指针、函数指针、函数指针数组（状态机与 ops 表）
  - 内存布局：栈、堆、BSS、数据段；static 的三种语义
  - 结构体对齐与 offsetof；volatile 到底解决什么
  - 手写数据结构：链表、栈、队列、哈希表
- Linux 环境与工程工具
  - Ubuntu、VSCode、Git 身份与 GitHub 仓库：已完成
  - Makefile 三步演化：显式规则 → 变量 → 模式规则加自动依赖（-MMD -MP）
  - GDB：断点、条件断点、watch、bt、frame、x/、core dump 分析
- 算法：本周开始，每周 2 题，只占周末
- 产出
  - GitHub 仓库 linux-study（已建）
  - 一个多文件 C 项目，-Wall -Wextra -Werror 零警告，能用 Makefile 编译、GDB 调试
  - 1 篇问题驱动的博客

### 2026.11：Linux 系统编程

- 文件 I/O：open/read/write/lseek/close、`FILE*` 与 fd 的关系、缓冲、errno 与 perror、umask
- 进程：fork/exec/wait、写时复制、僵尸进程与孤儿进程
- 线程：pthread、互斥锁、条件变量、生产者消费者
- 进程间通信：pipe/FIFO、共享内存加信号量、消息队列、mmap
- I/O 多路复用：select/poll/epoll，LT 与 ET 模式的坑
- 网络：TCP/UDP socket、字节序、粘包与拆包
- 配套工具：strace、ltrace，排查「程序卡住」的第一工具
- 产出
  - 主线项目进化到 v0.2（系统调用重写）、v0.3（多进程多线程）、v0.4（C/S 架构）
  - 多线程 TCP 文件服务器或聊天室
  - 技术博客 2—3 篇

### 2026.12：QEMU 上的驱动入门与硬件决策

先在 QEMU 上学原理，零成本、可无限次搞崩、能单步调内核：

- 用 Buildroot 生成 qemu_aarch64_virt 的内核与根文件系统，手工编译一次内核
- 动手重点：搞清内核、设备树、根文件系统三者各自是什么、怎么拼起来
- 内核模块：编写、编译、insmod/rmmod/lsmod/modinfo
- file_operations、字符设备注册（alloc_chrdev_region + cdev + class_create/device_create）
- 设备树基础语法：compatible、reg、interrupts、status

硬件决策，本月必须做完：

1. 先借：问师兄或导师借一块 Zynq-7000 板，大概率有且闲置
2. 借不到就买 i.MX6ULL（正点原子或野火，300—500 元），比 ZYNQ 更适合第一次上真板
3. 顺便买逻辑分析仪（100—300 元），调 I2C/SPI 时比自己猜时序快得多

其他：

- 复习 STM32：中断、DMA、I2C、SPI，面试会问裸机经历
- ARM 体系：寄存器组、异常等级、中断向量、MMU 基础、Cache 一致性概念

产出：QEMU 上跑通完整 Linux；第一个字符设备驱动，含注册、read/write、用户态测试程序。

### 2027.1：第一个驱动项目

- GPIO LED、按键中断、I2C 温湿度传感器。有真板就在真板上做，没有就继续 QEMU 加虚拟设备
- 中断下半部：tasklet、工作队列、threaded IRQ 的选择依据
- 并发控制：自旋锁、互斥锁、信号量、原子操作
- 产出
  - 字符设备驱动加设备树加用户态测试程序，作为独立 Git 仓库
  - 项目 README 与调试记录，调试记录比代码值钱
  - 寒假复盘：完成第 18 节的能力验收自评

## 5. 研一下：2027.2—2027.6

### 2027.2—3：驱动进阶与 C++ 进主线

C++ 开始每日并行。学法是唤醒加补齐，不要读《C++ Primer》全本：

- 顺序：类与构造析构 → 拷贝控制（三/五法则）→ RAII 与智能指针 → 继承与虚函数 → 模板基础 → 移动语义
- 最佳练法：把研一上写的 C 项目用 C++ 重写一遍。同一个问题两种语言解，面试直接可讲
- 参考《Effective C++》《Effective Modern C++》做查漏，语法查 cppreference，以写代读
- 刷题时刻意用 C++ 的方式写，比如用 unique_ptr 管链表节点，刷题本身就在练 C++
- 注意：用 C++ 刷题不等于会 C++。刷题用不到类、拷贝控制、虚函数、模板、移动语义，这些要单独补

驱动进阶：

- platform 驱动模型、probe/remove、设备树匹配
- 输入子系统、I2C/SPI 子系统（i2c_driver、i2c_client、i2c_adapter 的关系）
- 中断上下半部划分、request_threaded_irq
- 并发保护实战：说清楚你保护了哪个数据结构、为什么选那把锁

产出：一个 platform 驱动项目，一个 I2C/SPI 传感器驱动。

### 2027.4：系统移植（上真板）

- U-Boot 移植与裁剪：board_init、DDR 初始化、启动流程
- Linux 内核配置、编译、裁剪：menuconfig、defconfig、启动时间优化
- 根文件系统：BusyBox 到 Buildroot
- 产出：从零构建可启动的嵌入式 Linux 系统，记录移植过程中每一个卡点
- 这一阶段再用 PetaLinux 这类厂商工具是合理的，因为底层原理已经懂了

### 2027.5：综合项目、简历、投日常实习

- 综合项目要往深挖型做，判断标准见第 11 节
- 简历：项目按 STAR 写，必须有数字，比如延迟、内存、吞吐、启动时间
- 投递：中小厂、初创公司、研究所的嵌入式软件或驱动实习

### 2027.6：面试、复盘与模拟

- 复习 C、C++、Linux、驱动、网络、操作系统
- 补 FreeRTOS：任务调度、信号量、队列。面试常问裸机与 RTOS 的对比
- 至少 3 次模拟面试，同学互面或录下来自己看，你会发现表达问题比知识问题多
- 产出：1—2 个可展示项目；第一份实习面试记录与复盘

### 开源贡献起步

目标不是给内核提交功能，现实路径是：

- Documentation 修正错误、drivers/staging 修编译警告和 checkpatch 问题、设备树补节点
- 或门槛更友好的项目：U-Boot、Buildroot、Zephyr、RT-Thread、LVGL、FFmpeg

- 节奏：每月 1 个补丁。第一个补丁花 2 个月很正常，第二个就快了。
- 前置技能：git rebase、format-patch、send-email，读懂 MAINTAINERS，会用 checkpatch.pl。

### 内核源码阅读

每月精读一个子系统的最小闭环，从用户态入口一路追到内核。工具用 elixir.bootlin.com，配本地 cscope 或 ctags 索引。

| 月份 | 专题 |
| :-- | :-- |
| 9 月 | open() → sys_open → do_sys_open → vfs_open |
| 10 月 | read/write 的 VFS 路径与字符设备 file_operations |
| 11 月 | module_init 到模块注册的完整链路 |
| 12 月 | platform_driver_register 与设备树 `of_*` 解析 |

## 11. 项目作品集

原则：宁要一个能讲 20 分钟的项目，不要六个只能讲 2 分钟的。

深挖型的判断标准不是功能多，而是有指标、有对比、有取舍：

| 教程型（不要） | 深挖型（要） |
| :-- | :-- |
| 用 MQTT 把温湿度传到服务器 | 网关在 200 并发下内存从 8MB 涨到 40MB，用 valgrind 和 perf 定位到是每条消息都 malloc 了一个 4KB 缓冲，改成环形缓冲池后稳定在 12MB，P99 延迟从 80ms 降到 9ms |
| 我移植了 U-Boot | 卡在 DDR 初始化，通过对比 vendor 的 SPD 参数和 readl 打印寄存器值定位到问题，记录在文档里 |
| 我写了字符设备驱动 | 我的驱动在中断里调用 copy_to_user 导致偶发 oops，改用工作队列加环形缓冲后消除，附 ftrace 截图证明中断延迟改善 |

推荐的作品组合，3 加 1：

1. 主线进化项目，同一个项目连续 4 周进化，展示从 libc 到系统调用到并发到网络的完整能力链。Git 历史本身就是成长曲线
   - W1 多文件 C 加 Makefile 加 GDB
   - W2 系统调用重写加 errno
   - W3 多进程多线程
   - W4 Socket C/S
2. 深挖型性能或稳定性项目，有数据、有对比、有取舍的那一个，最重要
3. ZYNQ 差异化项目，PS-PL 协同：PL 侧一个 AXI 外设，PS 侧 Linux 驱动控制它，进阶 AXI DMA 加边缘推理。这个项目同时供论文和求职用
4. 开源贡献记录。不需要是项目，一个被合并的补丁就是一个作品

备选练习项目，做过即可，不必都做：I2C/SPI 传感器采集加 MQTT 加 SQLite、智能家居网关、V4L2 加 FFmpeg 加 RTSP 视频监控、RK3568 NPU 部署 YOLO。

## 12. 技能优先级

### T0：必须熟练

- C 进阶、Linux 系统编程
- Git、Makefile、GDB
- 数据结构：链表、队列、栈、哈希
- 操作系统：进程、线程、内存、文件系统

### T1：岗位核心

- C++：类与构造析构、拷贝控制、RAII 与智能指针、继承与虚函数、模板基础、移动语义、STL
- 字符设备驱动、设备树、platform 驱动
- 中断上下半部、并发控制：自旋锁、互斥锁、信号量、原子操作
- I2C/SPI 子系统
- U-Boot、内核裁剪、根文件系统
- ARM 体系结构：异常等级、MMU、Cache 一致性

### T2：加分项

- FreeRTOS、Qt、Python
- 边缘 AI：ONNX、RKNN、DPU，至少端到端跑通一次

## 13. 节奏与止损

### 底线加弹性

不要设天花板，要设底线。

| 项 | 内容 |
| :-- | :-- |
| 底线（雷打不动） | 每天 1 小时，状态再差也要做。做不到就第二天补，不允许连续两天为零 |
| 弹性（上不封顶） | 状态好、周末、没课的时候做 4—8 小时，不设上限 |
| 止损机制 | 连续两周没达到底线，不要自责，立刻把当前任务砍掉一半，从最小可完成量重启 |

为什么不用「工作日 2—3 小时加周末 5—6 小时」：那个量对研一偏高，而且太脆。一旦某周没达标，人容易产生「我已经落后了」的挫败感然后彻底放弃，这是自学规划最常见的死法。

### 博客必须问题驱动

不要写《Linux 文件 I/O 学习笔记》，要写《我的 read() 在 NFS 上返回 0 但文件非空，一次 errno 排查记录》。

文章结构固定为：现象 → 我的错误猜测 → 排查过程 → 真正原因 → 如何避免。后者的价值是前者的 10 倍，因为它证明你解决过真实问题，面试时可以直接讲。

## 16. 避坑清单

1. 不要一直停留在 STM32 裸机，除非确定走 MCU 方向。
2. 不要只看视频不动手，驱动必须自己编译、加载、调试。
3. 不要忽略 Git、Makefile、GDB，它们不是附带的。
4. 不要等完全准备好才投实习，边投边补。
5. 不要只做教程项目，要做有指标、有对比、有取舍的深挖型项目。
6. 不要只写知识总结式博客，要写问题排查记录。
7. 不要等买开发板才开始，QEMU 今天就能开始。
8. 不要把 C++ 留到研二，它会成为面试的硬伤。
9. 不要看中文二手资料学内核，普遍滞后 5—10 年。
10. 不要装 PetaLinux 或 Yocto 入门，抽象层太厚，学不到原理。
11. 不要设高目标然后失败放弃，设底线，允许弹性。
12. 不要等到研二下才写简历，提前批 2028 年 1 月就开。
13. 不要做和毕业论文无关的项目，让论文和求职共用一件事。
14. 不要被动等导师安排，导师无指导时你要提案而不是请示。
15. 不要用 AI 生成你看不懂的代码，面试官会让你讲你自己的代码。

## 18. 能力验收标准

这是「学会」的定义。每条都要能用 3 分钟讲清楚，而不只是看过。每季度自测一次，答不上来的就是下季度的重点。

### C 与语言层

- `swap(void*, void*, size_t)` 怎么实现？为什么需要 size_t？
- 结构体对齐规则？struct {char c; int i; double d;} 的 sizeof 是多少，为什么？
- 函数指针数组怎么用于实现状态机或驱动 ops 表？
- volatile 在驱动里解决什么问题？它不解决什么问题？
- 栈、堆、BSS、数据段分别放什么？static 修饰局部、全局、函数各是什么语义？
- 一个段错误，你用哪几步定位到具体行？

### C++

- 虚函数表的内存布局？为什么基类析构要 virtual？
- unique_ptr 和 shared_ptr 的实现与开销差异？
- vector 扩容为什么是摊还 O(1)？
- 右值引用和移动语义解决了什么问题？
- 拷贝控制的三法则、五法则分别是什么？

### Linux 系统编程

- open() 到 vfs_open() 的完整调用链？
- fork 的写时复制怎么工作？vfork 和 clone 的区别？
- 进程间通信几种方式各自适合什么场景？为什么共享内存还需要配信号量？
- select、poll、epoll 的底层差异？epoll 的 LT 和 ET 模式区别与坑？
- TCP 服务端 accept 返回的 fd 和监听 fd 有什么不同？
- 多线程程序里 pthread_mutex 和自旋锁怎么选？

### 驱动与内核

- file_operations 里 read/write 的返回值语义？copy_to_user 为什么不能用 memcpy？
- kmalloc 和 vmalloc 的区别？各自能分配多大？中断上下文能用哪个？
- 自旋锁、互斥锁、信号量：选择依据是什么？中断上下文为什么不能睡眠？
- 中断上半部和下半部的划分原则？tasklet、工作队列、threaded IRQ 怎么选？
- 设备树是怎么变成 platform_device 的？compatible 属性在哪里被匹配？
- I2C 子系统里 i2c_adapter、i2c_client、i2c_driver 的关系？
- 内核 oops 日志里，你怎么从调用栈定位到出问题的行？
- 你的驱动有没有并发保护？具体保护了哪个数据结构、为什么选那个锁？

### 工程与调试

- Makefile 里的模式规则、自动变量、.PHONY、自动依赖（-MMD -MP）分别解决什么问题？
- 交叉编译一个内核模块需要哪几个东西？为什么不能用主机 gcc？
- perf top 和 ftrace function_graph 分别适合回答什么问题？
- 系统启动卡住了，你的排查顺序是什么？

如果这些现在一个都答不上来，完全正常，这就是三年要做的事。
