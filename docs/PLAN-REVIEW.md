## 二、必须改的 4 件事

### 1. 🔴 C++ 从 T2 提到 T1（最致命）

规划把 C++ 归在「T2 加分项」，和 Qt、Python 并列。这是对 2026 年招聘现实的误判。

真实的岗位语言分布：

| 岗位方向 | 主力语言 | 代表公司 |
| :-- | :-- | :-- |
| 驱动 / BSP / 内核 | C 为主，**但几乎必问 C++ 基础** | 华为、中兴、海康、大华、比亚迪 |
| 应用 / 中间件 / 系统软件 | **C++ 为主** | 大疆、小米、OPPO、vivo、TP-LINK |
| 智能汽车 / 自动驾驶域控 | **C++ 很重** | 蔚来、理想、小鹏、地平线、华为车 BU |
| 边缘 AI / 端侧推理 | C++ + Python | 瑞芯微、地平线、寒武纪 |

后果很具体：**你的简历能过，但面试会挂在 C++ 上。** 而 C++ 从零到「面试能答」需要 3—4 个月，如果研二下（2028.3）才想起来补，正好撞上暑期实习投递。

**修正动作：**
- 2027.2 起，把 C++ 列为和 Linux 系统编程同级的每日任务。
- 学习顺序（不要一上来啃《Effective C++》）：`类与对象/构造析构` → `引用与 const` → `运算符重载` → `继承与虚函数/多态` → `RAII 与智能指针` → `STL 容器与迭代器` → `模板基础` → `移动语义` → `C++11/14/17 常用特性`。
- **最好的练法：用 C++ 重写你研一上写的那个 C 项目。** 同一个问题用两种语言解，你会真正理解 RAII、值语义、运行时多态和 C 的差别，面试时这就是现成的对比素材。
- 面试高频点你必须能讲：虚函数表的内存布局、为什么基类析构要 virtual、`unique_ptr` vs `shared_ptr` 的实现与开销、为什么 `vector` 扩容是摊还 O(1)、右值引用解决了什么问题。

### 2. 🟠 刷题从 2027.9 提到本周

规划把 LeetCode Hot 100 放在研二上。问题是：**大厂笔试/机考是硬门槛，过不了机考，后面的八股和项目一点用都没有。** 而 Hot 100 第一遍需要 3—4 个月才能消化（不是刷完，是内化）。

**修正动作：**
- 每周 **2 题**，只在周末做，不占用工作日。这样 2027.6 前能完成第一遍。
- 按专题刷，不按题号刷：数组/双指针 → 链表 → 哈希 → 字符串 → 二叉树 → 栈队列 → 排序二分 → 动规 → 图。
- **必须写题解**（哪怕 3 行），否则一个月后等于没做。题解直接进 `notes/leetcode/`，Git 提交就是记录。
- 嵌入式岗位机考难度通常低于互联网，但**手撕代码**环节很常见（写一个单链表反转、写个字符串处理函数）。

### 3. 🟡 开发板之前，先用 QEMU（今天就能开始）

规划让你买正点原子/野火 i.MX6ULL。板子该买，但**不该是起步的第一件事**：

- 下单到收货 + 配好交叉编译环境 + 搞定串口/网络，现实里要 1—2 周。
- 起步阶段最容易的失败模式就是「等硬件期间停下来」，然后就没有然后了。
- 你现在没插任何 USB 转串口设备，也没有交叉工具链 —— 也就是说，按原规划，你这两周无事可做。

而你有 20 核 15 G 内存的机器，**QEMU 能让你今天下午就跑起一个 aarch64 Linux 并加载自己的内核模块**：

```bash
# 大致路径（第 3—4 周才做，先有个印象）
sudo apt install qemu-system-arm gcc-aarch64-linux-gnu buildroot
# 用 Buildroot 生成 qemu_aarch64_virt_defconfig 的 内核 + 根文件系统
# qemu-system-aarch64 -M virt -cpu cortex-a57 -kernel Image -drive ... 
```

QEMU 相对真板的优势，恰恰是学习期最需要的：**可无限次搞崩、可单步调试内核、可 dump 内存、能看到完整启动日志、零成本。** 真板的优势是 GPIO/I2C/SPI 这些真实外设。

**修正动作：**
- **2026.10 — 2026.11**：QEMU + Buildroot，先跑通「编译内核 → 启动 → 加载 hello 模块 → 卸载」。
- **2026.12**：真需要 GPIO LED / 按键中断 / I2C 传感器时，再买 i.MX6ULL（正点原子或野火都行，约 300—500 元）。同时考虑一台逻辑分析仪（约 100—300 元），调试 I2C/SPI 时价值极高。

### 4. 🟠 补上「开源贡献」这条线

规划里完全没有开源贡献。但对嵌入式/驱动岗，**一个被 merged 的 patch 的说服力，大于三个教程项目**，因为它证明了三件面试官最想知道的事：你能读真实的大型代码库、你能遵守社区规范、你的代码被别人 review 过。

**修正动作（从研二上开始，别更早）：**
- 目标不是「给 Linux 内核提交功能」，那是幻想。现实路径：
  - `Documentation/` 修正错误、`drivers/staging/` 修编译警告和 checkpatch 问题、设备树里补一个缺失的节点、`scripts/` 小工具修复。
  - 或转向门槛更友好的项目：**U-Boot、Buildroot、Zephyr、RT-Thread、LVGL、FFmpeg**。
- 节奏：**每月 1 个 patch**。第一个 patch 花 2 个月很正常，第二个就快多了。
- 前置技能：`git` 到能熟练用 `rebase`/`format-patch`/`send-email`、读懂 `MAINTAINERS`、会用 `checkpatch.pl`、能承受「被 maintainer 怼」。

## 三、建议增强的 5 个点

### 5. 项目要从「教程型」升级为「深挖型」

规划第 9 节列的 6 个项目（智能家居网关、数据采集、视频监控、边缘 AI…）都是**每年面试官会看到几百份的同质项目**。它们作为练习没问题，但需要一个「能讲 20 分钟」的深挖型作品。

深挖型项目的判断标准，**不是功能多，而是有指标、有对比、有取舍**：

| ❌ 教程型 | ✅ 深挖型 |
| :-- | :-- |
| 「我用 MQTT 把温湿度传到服务器了」 | 「网关在 200 并发下内存从 8MB 涨到 40MB，我用 valgrind + perf 定位到是每条消息都 malloc 了一个 4KB 缓冲，改成环形缓冲池后稳定在 12MB，P99 延迟从 80ms 降到 9ms」 |
| 「我移植了 U-Boot」 | 「我移植时卡在 DDR 初始化，通过对比 vendor 的 SPD 参数和 readl 打印寄存器值定位到问题，记录在文档里」 |
| 「我写了字符设备驱动」 | 「我的驱动在中断里调用 copy_to_user 导致偶发 oops，改用工作队列 + 环形缓冲后消除；附 ftrace 截图证明中断延迟」 |

**没有数据和取舍的项目，面试官问不到三层就结束了。**

### 6. 加一条「内核源码阅读」线

驱动岗面试几乎必问：「你读过内核哪部分的源码？」规划完全没安排这件事。

**修正动作：每月精读 1 个子系统的最小闭环**，读法是从用户态入口一路追到内核：
- 10 月：`open()` → `sys_open` → `do_sys_open` → `vfs_open`
- 11 月：`read()`/`write()` 的 VFS 路径 + 字符设备 `file_operations`
- 12 月：`module_init` 到 `module_register` 的完整链路
- 之后：`platform_driver_register`、设备树 `of_*` 解析、I2C 子系统、中断子系统

工具：`https://elixir.bootlin.com`（在线交叉引用，必备）+ `cscope`/`ctags` 本地建索引。

### 7. 把「调试能力」从工具列表变成一个技能项

规划把 GDB、示波器、逻辑分析仪列在「调试工具」里，但没当成训练科目。实际上**调试能力是嵌入式岗区分度最高的能力**，因为它无法速成。

必须练到熟练的清单：
- `gdb`：断点/条件断点/`watch`/`bt`/`frame`/`x/`、分析 core dump、attach 到运行中进程
- `strace`/`ltrace`：黑盒看系统调用（排查「程序卡住了」的第一工具）
- `valgrind`/`ASan`：内存泄漏与越界
- `perf` + `ftrace`：性能剖析、函数调用图、调度延迟
- `objdump`/`readelf`/`nm`：看 ELF、反汇编、段布局
- 内核侧：`dmesg`、`printk` 分级、`pr_debug` + dynamic debug、分析 oops 调用栈
- 硬件侧：万用表、示波器看时序、逻辑分析仪抓 I2C/SPI 波形

### 8. 补上「AI 工具 + 端侧部署」

2026 年的现实：会用 AI 工具提效、能部署端侧模型，都是加分且相对稀缺的技能。规划只把「边缘 AI」列为方向选项之一，没当成基本技能。

- **工具侧**：日常可以用 Copilot/Claude Code 之类，但守住底线 —— **每个提交的代码你都必须能一行行解释**。面试官会让你讲你自己的代码。
- **端侧侧**：研二前至少跑通一次完整链路 `PyTorch 训练 → 导出 ONNX → 量化 → RKNN/NPU 推理`，哪怕模型很小。这对你「电子信息工程」背景是最自然的差异化方向。

### 9. 英文能力要具体化为可执行动作

「能读手册」不是动作。改成：
- **每周精读 1 篇 [LWN.net](https://lwn.net) 文章**（内核社区动态，读久了你会知道社区在吵什么，面试加分）。
- **每月精读 1 份 datasheet 的 1 个章节**（比如你手上传感器的 I2C 时序章节）。
- 遇到不认识的术语，直接去读内核文档 `Documentation/` 原文，不要只看中文二手资料 —— **二手资料普遍滞后内核 5—10 年**，这是嵌入式学习最大的坑之一。

## 五、能力自检清单（面试官真正会问的）

这份清单是**「学会」的验收标准**。每一条你都要能用 3 分钟讲清楚，而不只是「看过」。建议每季度自测一次，答不上来的就是下季度的重点。

**C / 语言层**
- [ ] `swap(void*, void*, size_t)` 怎么实现？为什么需要 `size_t`？
- [ ] 结构体对齐规则？`struct {char c; int i; double d;}` 的 `sizeof` 是多少，为什么？
- [ ] 函数指针数组怎么用于实现状态机/驱动 ops 表？
- [ ] `volatile` 在驱动里到底解决什么问题？它**不**解决什么问题？
- [ ] 栈、堆、BSS、数据段分别放什么？`static` 修饰局部/全局/函数分别是什么语义？
- [ ] 一个段错误，你用哪几步定位到具体行？

**Linux 系统编程**
- [ ] `open()` 到 `vfs_open()` 的完整调用链？
- [ ] `fork` 的写时复制（COW）具体怎么工作？`vfork` 和 `clone` 的区别？
- [ ] 进程间通信几种方式各自适合什么场景？为什么共享内存还需要配信号量？
- [ ] `select` / `poll` / `epoll` 的底层差异？epoll 的 LT 和 ET 模式区别与坑？
- [ ] 一个 TCP 服务端，`accept` 返回的 fd 和监听 fd 有什么不同？
- [ ] 多线程程序里，`pthread_mutex` 和自旋锁怎么选？

**驱动 / 内核**
- [ ] `file_operations` 里 `read`/`write` 的返回值语义？`copy_to_user` 为什么不能用 `memcpy`？
- [ ] `kmalloc` 和 `vmalloc` 的区别？各自能分配多大？在中断上下文能用哪个？
- [ ] 自旋锁 vs 互斥锁 vs 信号量：选择依据？中断上下文为什么不能睡眠？
- [ ] 中断上半部和下半部的划分原则？tasklet / 工作队列 / threaded IRQ 怎么选？
- [ ] 设备树是怎么变成 `platform_device` 的？`compatible` 属性在哪里被匹配？
- [ ] I2C 子系统里 `i2c_adapter` / `i2c_client` / `i2c_driver` 的关系？
- [ ] 内核 oops 日志里，你怎么从调用栈定位到出问题的行？
- [ ] 你的驱动有没有并发保护？讲讲你具体保护了哪个数据结构、为什么选那个锁。

**工程 / 调试**
- [ ] Makefile 里的模式规则、自动变量、`.PHONY`、自动依赖（`-MMD -MP`）分别解决什么问题？
- [ ] 交叉编译一个内核模块，需要哪几个东西？为什么不能用主机 gcc？
- [ ] `perf top` 和 `ftrace function_graph` 分别适合回答什么问题？
- [ ] 系统启动卡住了，你的排查顺序是什么？

**如果这些你现在一个都答不上来 —— 完全正常，这就是三年要做的事。** 把这份清单存下来，每季度过一遍，你会看到自己的变化。

## 六、节奏修正：设底线，不设天花板

原规划：工作日 2—3 小时 + 周末 5—6 小时 ≈ **23—25 小时/周**。

这个量对研一（有课、有实验室任务）是偏高的。**问题不在于它太累，而在于它太脆** —— 一旦某周没达到，人就容易产生「我已经落后了」的挫败感，然后彻底放弃。这是自学规划最常见的死法。

建议改成 **「底线 + 弹性」**：

| | 内容 |
| :-- | :-- |
| **底线（雷打不动）** | 每天 **1 小时**，状态再差也要做。做不到就在第二天补，不允许连续两天为零。 |
| **弹性（上不封顶）** | 状态好、周末、没课的时候做 4—8 小时。不设上限，因为热情来了不该被规划限制。 |
| **硬约束 1** | 每周 **≥3 次 Git 提交**（这条比「学了多少」更重要，它是唯一客观的产出证据） |
| **硬约束 2** | 每两周 **≥1 篇博客**（problem-driven） |
| **硬约束 3** | 每周 **2 道算法题**（周末） |
| **止损机制** | 连续两周没达到底线 → 不要自责，**立刻砍掉当前任务的一半**，从最小可完成量重新开始。 |

关于博客的一条重要提醒：**不要写知识总结。**「Linux 文件 I/O 详解」这种文章，你自己一周后都不会再看。要写 **problem-driven** 的：

> ❌ 《Linux 文件 I/O 学习笔记》
> ✅ 《我的 read() 在 NFS 上返回 0 但文件非空 —— 一次 errno 排查记录》

后者的价值是前者的 10 倍：它证明你解决过真实问题，面试时可以直接讲，而且写作过程本身就是复盘。
