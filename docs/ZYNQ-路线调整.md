# ZYNQ 背景下的路线调整

> **触发信息**：实验室方向主要是 ZYNQ；导师目前无具体指导，基本靠自学。
> **结论**：这两个信息合起来，其实是**一个明显的机会**，但原 `README.md` 里完全没有体现。需要把路线往 ZYNQ 上靠一部分。

---

## 一、为什么 ZYNQ 是关键信息

ZYNQ-7000 是 Xilinx 的 SoC：**双核 ARM Cortex-A9 + FPGA 可编程逻辑**在同一芯片上。这意味着你的实验室环境天然覆盖了两件事：

1. **ARM + 嵌入式 Linux**（Cortex-A9 跑 Linux，就是你的求职主线）
2. **软硬协同 / 硬件加速**（PL 侧做加速器，PS 侧 Linux 驱动调用它）

这条路径在就业市场上**非常有辨识度**，因为它同时命中了三类岗位：

| 岗位类型 | 为什么 ZYNQ 经验加分 | 代表去处 |
| :-- | :-- | :-- |
| 嵌入式 Linux / 驱动 / BSP | ZYNQ 的 Linux 移植（PetaLinux）本质上就是 U-Boot + 内核 + 设备树 + 根文件系统，和 i.MX6ULL 学的东西是同一套 | 华为、中兴、海康、大华、比亚迪 |
| FPGA / 软硬协同 / 异构计算 | 会 PS-PL 协同、AXI 总线、DMA 的人比纯软件的人少得多 | AMD(Xilinx)、中电科各所、航天科工、雷达/通信研究所 |
| 边缘 AI / 异构推理 | ZYNQ 有 DPU（深度学习处理单元）IP，PYNQ 生态，是端侧推理的经典平台 | 地平线、瑞芯微、寒武纪、工业视觉公司 |

**关键点：你的电子信息工程背景 + ZYNQ 实验室，本来就站在这条交叉路口上。** 原规划把「边缘 AI」列为研二的一个可选方向，实际上对你来说它可能是**阻力最小的主攻方向**。

## 二、但要避免的坑：不要把 ZYNQ 当成入门平台

ZYNQ 是**很重**的平台，直接用它在研一上入门会踩三个坑：

1. **工具链巨大且脆弱。** Vivado + Vitis + PetaLinux 加起来 100 GB 以上，安装和版本匹配能消耗掉你好几周，而且动不动就环境崩。
2. **抽象层太厚，学不到原理。** PetaLinux 会帮你把设备树、内核配置全部生成好。你按教程敲完一遍，可能完全不知道 `system-user.dtsi` 里那几行到底在干什么。**这恰恰是面试要问的东西。**
3. **资料是英文且分散。** Xilinx 的文档质量高但体量大（UG 文档动辄几百页），新手容易迷失。

**所以正确顺序是：先在没有抽象层的地方把原理打通，再用 ZYNQ 做应用和差异化。**

## 三、调整后的路线：三层递进

```
第一层（2026.10 — 2026.12）  QEMU + 手工 Buildroot
     └─ 目的：理解「内核 + 设备树 + 根文件系统」到底是怎么回事，没有厂商工具帮你藏东西
     └─ 产出：从源码编译内核，QEMU 启动，写自己的字符设备驱动并加载

第二层（2026.12 — 2027.3）  借实验室的 ZYNQ 板，手工移植（不用 PetaLinux）
     └─ 目的：把第一层学到的原理，搬到真实硬件上，而且用 u-boot + 内核 + 设备树手动拼
     └─ 产出：ZYNQ 上跑起自己构建的 Linux；写 GPIO / 中断 / I2C 驱动
     └─ 额外动作：主动问师兄/导师「实验室有没有闲置的 Zynq-7000 板子可以借」

第三层（2027.3 起）  PS-PL 协同 + 边缘 AI（这是你的差异化）
     └─ 目的：做出别人做不出的东西 —— 这时候再用 PetaLinux/Vitis 是合理的，因为你已经懂底层了
     └─ 产出：PL 侧一个简单 AXI 外设（比如 PWM/计数器），PS 侧写 Linux 驱动去控制它
     └─ 进阶：AXI DMA + 一个小的卷积加速器 + DPU 部署
```

**动作项（本周就做，5 分钟）：**
> 给导师或师兄发一条消息：「实验室是否有 Zynq-7000 开发板可以借我用来做 Linux 驱动和软硬协同的学习？」—— 大概率是有的，而且闲置。这能直接省下买板子的钱，还比 i.MX6ULL 更贴你的实验室环境。

## 四、导师「无指导」的双面性

这不是纯粹的坏事，但要主动管理：

**好的一面**
- 你的时间完全自主，不会被横向项目占满（这是很多研究生的最大痛点）。
- 没有人在方向上说「你别搞那个」，你可以自由地把重心放在求职上。

**风险的一面（必须自己解决）**
- **没有项目 → 简历上没有实验室经历。** 面试官会问「你研究生期间做什么课题」，如果答不上来会很尴尬。
- **毕业论文没有方向 → 研三会非常痛苦。** 无指导的学生最容易在研二下发现「论文还没开始」。
- **没有 deadline → 容易松散。** 这正是我在 `PLAN-REVIEW.md` 第六节强调「设底线」的原因。

**应对策略：让论文和求职共用同一个项目。**

这是最重要的一条建议。**不要做两件事，要做一件能同时产出论文和简历的事。** 一个可行方向：

> **「基于 ZYNQ 的边缘视觉推理系统的设计与实现 —— 从 Linux 驱动到硬件加速」**

这个题目可以拆出：
- 一篇能毕业的论文：某个具体环节的优化（比如「基于 AXI DMA 的零拷贝图像传输」或「面向 ZYNQ DPU 的模型量化与部署优化」）
- 一个能进简历的项目：完整的 Linux + 驱动 + 加速链路
- 面试可讲的深度：你懂 DMA、内存一致性、cache 维护、驱动并发

**动作项：** 2027 年上半年就要和导师谈一次毕业论文方向，**带着 2—3 个自选题目去谈**（而不是问「老师我做什么」）。导师无指导时，你需要「提案」，不是「请示」。

## 五、对 C++ 计划的微调

你说「学过但忘得差不多，刷 LeetCode 时会用 C++」。这个状态比「完全没学过」好得多，但有个**重要的认知陷阱**：

> **用 C++ 刷 LeetCode ≠ 会 C++。**

LeetCode 上的 C++ 实际上只是「带 STL 的 C」—— 你会用到 `vector`、`string`、`unordered_map`，但**完全用不到**：

| 刷题练不到的（恰恰是面试要问的） | 为什么练不到 |
| :-- | :-- |
| 类、构造/析构、拷贝控制 | 刷题不写类 |
| RAII、`unique_ptr`/`shared_ptr` | 刷题用裸指针或容器 |
| 虚函数、多态、虚函数表 | 刷题不写继承 |
| 模板、移动语义、右值引用 | 刷题不涉及 |
| 编译链接、头文件组织、ABI | 刷题是单文件 |

**所以计划维持 `PLAN-REVIEW.md` 的建议（2027.2 起进主线），但学习方式改为「唤醒 + 补齐」而不是「从零」：**

1. **先唤醒**：把研一上写的 `minitool` 项目用 C++ 重写一遍。你会立刻发现 C 和 C++ 的思维差异。
2. **再补齐**：按这个顺序专项突破刷题练不到的部分 —— `类与构造析构` → `拷贝控制（三/五法则）` → `RAII 与智能指针` → `继承与虚函数` → `模板基础` → `移动语义`。
3. **参考书**：不要读《C++ Primer》全本（太厚，会卡住）。用《Effective C++》/《Effective Modern C++》做查漏，配合 cppreference 查语法。**以写代读。**
4. **刷题策略调整**：既然你用 C++ 刷题，那就**刻意用「C++ 的方式」写题解** —— 用 `unique_ptr` 管理链表节点、用 RAII 管理资源。这样刷题本身就在练 C++。

## 六、更新后的硬件决策

| 时间 | 硬件 | 说明 |
| :-- | :-- | :-- |
| 2026.10 — 11 | **不买任何东西**，用 QEMU | 零成本，今天就能开始，学的是纯原理 |
| 2026.12 | **先借**实验室的 ZYNQ 板 | 本周就发消息问。借到就不用买 |
| 2026.12 | 若无 ZYNQ 可借 → 买 **i.MX6ULL**（300—500 元） | i.MX6ULL 更简单、资料更多，作为「第一次上真板」更稳 |
| 2027 上半年 | 逻辑分析仪（100—300 元） | 调 I2C/SPI 时价值极高，比自己猜时序快 10 倍 |
| 2027 下半年 | ZYNQ 板（若实验室始终没有） | 到这一步你已经有判断力了，自己选型号 |

**注意：不要一开始就买 ZYNQ 板自学**，除非你确定要走 FPGA 方向。原因见第二节的「坑」。

## 七、一句话总结

**ZYNQ + 无指导 = 你要主动把「实验室平台」变成「简历项目 + 毕业论文」，而不是等着导师安排。**

具体三步：
1. **本周**：问师兄/导师借一块 Zynq-7000 板子。
2. **2027 上半年前**：带着自选题目去找导师谈毕业论文方向，让论文和求职项目合并成一件事。
3. **2027 起**：走「QEMU 学原理 → ZYNQ 上真板 → PS-PL 协同 / 边缘 AI」三层递进，把 ZYNQ 做成你的差异化标签。
